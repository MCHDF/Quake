# Quake

Paper 서버용 미니게임 플러그인입니다. 현재 참여 메뉴와 시작 전 카운트다운을 구현했으며, 실제 게임 진행은 개발 중입니다.

## 이 프로젝트는 OpenAI Codex와 함께 개발하고 있습니다.

## 환경

- JDK 25 · Paper 26.3 · Gradle 9.7.0 (Wrapper 포함)

## 기능

- 접속 시 메뉴 책 지급, 우클릭으로 Dialog 참여 메뉴 열기
- 월드별 참가 인원·로테이션 대기 시간 보스바 및 30초 시작 카운트다운 표시
- 참여 취소·접속 종료 시 카운트다운 초기화 (남은 인원이 최소 인원 이상이면 처음부터 다시 시작)
- 일반 유저의 메뉴 책 드롭 제한
- `/quake` 명령어는 `quake.command` 권한 필요 (기본값: OP)
- `/quake get book` 명령어로 책 재지급
- `/quake setTimer <seconds>` 명령어로 게임 시간 설정 (기본 180초, 양의 정수). 다음 게임부터 적용되며 서버 재시작 후에도 유지됩니다.
- 게임 시작 시 RED/BLUE 팀 무작위 균등 배정 (최소 1:1, 홀수 인원은 한 명 차이). 상대 팀의 머리 위 닉네임을 숨기고 종료·퇴장 시 기존 스코어보드를 복원합니다.
- 게임 중 한 팀이 모두 나가면 게임을 취소하고 남은 인원은 다음 게임에 자동 참여
- 게임 참여자에게만 보이는 탭 목록: 팀 색상·팀별 묶음 정렬, 헤더·푸터, 이름 옆 처치 수 표시. 푸터에 각 팀의 총 처치 수 합계를 실시간으로 표시합니다. 종료·퇴장 시 기본 탭 목록으로 복원됩니다.

## 코드 구조

- `menu/MinigameMenu`: 참여 Dialog 화면과 버튼 처리
- `menu/MenuBook`: 메뉴 책 생성·지급·식별
- `listener/PlayerListener`: 접속·퇴장·책 사용·드롭 이벤트 연결
- `game/GameSession`: 참여 명단·다음 게임 대기열, 상태 전환 및 시작·종료 처리
- `game/GameState`: 대기·카운트다운·게임 진행 상태
- `game/GameTimer`: 카운트다운과 게임 시간의 반복 작업 실행·취소
- `game/GameDisplay`: 보스바 표시와 카운트다운 효과음
- `game/GameSettings`: 최소 인원·카운트다운 설정, 게임 시간 조회·저장
- `game/GameTeams`: 팀 배정, 상대 팀 닉네임 숨김, 스코어보드 복원
- `command/QuakeCommand`: 관리자 명령어 처리
- `database/DatabaseManager`: HikariCP 기반 SQLite 연결 풀 관리
- `database/GameWorldRepository`: SQLite 게임 월드 등록 목록 저장·조회·삭제
- `Quake`: 구성 요소 생성과 등록, 종료 시 정리

## 빌드 및 실행

```bash
./gradlew build      # 빌드
./gradlew runServer  # 개발 서버 실행
```

Windows에서는 `./gradlew` 대신 `.\gradlew.bat`을 사용합니다.

빌드 결과: `build/libs/Quake-1.0.0-all.jar` — Paper 서버의 `plugins` 폴더에 넣어 사용합니다.

게임 월드는 게임 내에서 관리자 명령어로 생성·삭제·이동할 수 있습니다.

```text
/quake world create <name>
/quake world delete <name>
/quake world tp <name>
/quake world list
```

월드 생성 이름에는 영문, 숫자, `_`, `-`만 사용할 수 있습니다. 삭제할 월드에는 다른 플레이어가 없어야 하며, 현재 위치한 월드는 삭제할 수 없습니다.

## 게임 월드 저장

게임 월드 이름은 `plugins/Quake/quake.db`의 `game_worlds` 테이블에 저장됩니다.
서버 시작 시 등록된 월드를 자동으로 불러오며, 목록과 선택 메뉴에는 등록되어 로드된 게임 월드만 표시됩니다.
블록·청크·기본 월드 스폰은 기존 월드 폴더에, 팀별 스폰은 SQLite에 저장하므로 백업할 때는 서버를 종료하고 DB 파일과 월드 폴더를 함께 복사하세요.
월드 파일이 없으면 경고를 남기고 로드를 건너뛰며, 빈 월드를 자동 생성하지 않습니다.

기존 버전의 월드는 자동 등록되지 않습니다. 월드 폴더를 백업한 뒤 해당 월드가 로드되지 않은 상태에서
`/quake world create <기존 월드 이름>`을 실행하면 기존 폴더를 불러와 등록합니다.
이 명령은 기존 생성 동작처럼 게임 규칙·시간·스폰 위치를 초기화합니다.
삭제는 등록된 게임 월드에만 허용됩니다. 파일 삭제가 실패하면 등록은 해제된 상태로 남으므로
로그를 확인하고 남은 폴더를 정리해야 합니다.

### 월드 관리 정보

`game_worlds`에는 이름 외에 다음 정보를 저장합니다.

| 컬럼 | 내용 |
| --- | --- |
| `world_uuid` | 실제 Bukkit 월드 UUID (중복 등록 불가) |
| `display_name` | 목록·메뉴에 표시할 이름, 기본값은 월드 이름 |
| `status` | `READY`, `MAINTENANCE`, `DISABLED`; 신규 등록은 `MAINTENANCE` |
| `created_at` | 등록 시각, UTC ISO 8601 형식 |
| `created_by` | 생성 명령 또는 생성 Dialog를 실행한 플레이어 UUID |
| `rotation_order` | 준비 완료 전환 순번. 준비 해제 후 재등록하면 새 순번을 부여 |

기존 이름만 있는 테이블은 시작 시 자동으로 확장합니다. 기존 월드 UUID는 정상 로드 시 채우고,
알 수 없는 기존 등록 시각·생성자는 `NULL`로 유지합니다. UUID가 다르면 해당 월드를 게임 월드 목록에서 제외하고 경고합니다.
자동 로테이션은 `READY` 상태이며 정상 로드된 월드만 대상으로 합니다.
표시 이름을 SQL로 변경한 경우 서버를 재시작해야 메모리에 반영됩니다. 상태는 순서 갱신과 스폰 검증을 위해 아래 명령어로 변경하세요.

### 월드별 인원 설정

`min_players`와 `max_players`의 기본값은 각각 2명(1:1), 16명(8:8)입니다.
두 값 모두 2~16 사이의 짝수만 허용하며, 최소 인원은 최대 인원 이하여야 합니다.
Java 검증과 SQLite CHECK 제약으로 명령어 및 직접 SQL 수정 모두에 적용합니다.
기존 DB도 시작 시 기본값으로 자동 확장됩니다.

```text
/quake world players desert_arena 4 12
```

명령어는 DB와 메모리의 월드 설정을 함께 갱신합니다.
게임은 현재 로테이션 월드의 최소 인원을 충족해야 시작 카운트다운에 진입하며, 시작 시 최대 인원까지만 참여합니다.

### 준비된 월드 로테이션

양 팀 스폰이 설정되고 정상 로드된 `READY` 월드를 준비 완료 순서로 순환합니다.
새로 준비된 월드는 현재 진행 중인 로테이션 대기 목록의 마지막에 추가됩니다. 각 월드는 참가자를 최대 30초 동안 기다립니다.
최소 인원이 충족되면 즉시 기존 30초 게임 시작 카운트다운을 시작하고 로테이션 대기는 중단합니다.
인원이 부족한 채 30초가 지나면 참가 신청을 유지한 채 다음 월드를 선택합니다.
준비된 월드가 없으면 게임을 시작하지 않고 30초마다 다시 확인합니다.

게임 시작 시 신청 순서대로 해당 월드의 최대 인원까지 팀 배정 후 각 팀의 스폰 지점으로 이동하고,
초과 인원은 다음 게임 대기열로 넘깁니다. 게임 종료·취소 시 다음 월드로 로테이션하며,
온라인 참가자는 게임 시작 전 위치로 돌아갑니다.
카운트다운 중 이탈하면 카운트다운을 초기화하며, 최소 인원 미달이면 해당 월드에서 다시 30초 동안 기다립니다.

### 월드 준비와 팀 스폰

새 월드는 `MAINTENANCE`(점검 중) 상태로 생성되며 목록과 메뉴에도 상태가 표시됩니다.
맵 제작 후 각 팀의 시작 위치에 서서 아래 명령을 실행하세요. 좌표와 시선 방향(yaw/pitch)을 함께 저장합니다.

```text
/quake world spawn arena red
/quake world spawn arena blue
/quake world status arena ready
```

양 팀 스폰을 모두 설정해야 `READY`로 전환할 수 있습니다. 준비 완료를 다시 실행해도 순서는 바뀌지 않습니다.
점검 또는 사용 중지 상태로 변경하면 이후 로테이션에서 제외됩니다.
다시 준비 완료로 전환하면 대기 목록 끝에 추가됩니다. 이미 진행 중인 게임은 끝까지 진행합니다.

```text
/quake world status arena maintenance
/quake world status arena disabled
```

스폰 수정은 해당 월드 안에서 점검 상태일 때만 가능하며, 게임 진행 중인 월드에서는 변경할 수 없습니다.
`world_spawns` 테이블에 월드 이름·팀(RED/BLUE)별로 x/y/z/yaw/pitch를 저장합니다.
기존 READY 월드도 팀 스폰이 없으면 로테이션에서 제외되므로 점검 상태로 전환한 뒤 스폰을 설정하세요.
DB의 순번과 스폰은 재시작 후에도 유지되며, 재시작 시 준비 완료 순번부터 새 로테이션을 시작합니다.
